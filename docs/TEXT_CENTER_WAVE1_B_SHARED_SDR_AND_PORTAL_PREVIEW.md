## New Linux cross-process guard

- Module: \`tihulu_runtime/sdr_crossprocess_guard.py\` with \`LinuxFlockSDRGuard\`, \`LinuxProcUSBUseAudit\` and a file-descriptor-backed reservation. Uses Linux \`flock(LOCK_EX|LOCK_NB)\` on one SHA256-named lock file per stable physical receiver identity; private shared lock directory mode 0700 and file mode 0600; \`O_NOFOLLOW\`, no input-derived disk paths; release on decoder STOP acknowledgment.
- Valid only on Linux and only with a **mandatory affirmative external-use audit**. The optional \`LinuxProcUSBUseAudit\` checks trusted physical \`/dev/bus/usb/BBB/DDD\` character node mappings against readable \`/proc/*/fd\`. Any unknown mapping, permission-denied process table or uncertain check blocks tuning. A user must not enter bus paths directly into untrusted browser controls.
- Guard controls **cooperating processes** that deliberately share the lock directory/device identity. It does **not** prevent a non-cooperating Gqrx, rtl_433, welle.io, dump1090, readsb or another privileged process from opening USB *after* the audit. A single RF supervisor/real device monitor or controlled process migration plus physical tests are mandatory before marketing this as globally protected physical SDR.
- Existing in-process \`SDRResourceBroker\` still handles Kit owner-scoped app leases; the Text Center bridge acquires the shared cross-process reservation before its in-process lease, without killing/preempting protected Flight Radar/Radio work. Actual FM/RDS process backend remains **NOT wired**, so the system never starts radio based on this guard alone.
- Unit tests: separate Python process holds the lock while another process is rejected; same-process independent handles collide, different receiver IDs remain independent; symlink/bad directory and missing audit reject; invalid IDs reject. Real radio hardware tests are **NOT performed**.
- Suggested future deployment path: privileged broker-created \`/run/lock/tihulu-rf\` private directory, stable USB serial+bus identity registry owned by trusted device service, same lock protocol adopted by **all** managed SDR callers (Flight Radar/readsb, Radio, RTL-433, Text Center), and verified process/fd audit. No system service, udev rule, or privileged daemon was installed in this PR.

## Incremental original UI under Kit portal

- Module \`tihulu_runtime/text_center_portal.py\` defines \`TextCenterPortalWSGI\`: owner-authenticated **GET only** routes for \`/text-center/\`, \`/text-center/assets/styles.css\`, \`/text-center/assets/kit-app.js\`, \`/text-center/assets/kit-mode.css\`, and \`/text-center/favicon.svg\`. Real source HTML/CSS/favicon loaded through strict fixed allowlist with size limits/symlink escape prevention; dangerous original standalone \`/assets/app.js\` and all standalone POST endpoints are **not** exposed.
- Existing \`tihulu_runtime/text_center_http.py\` provides the read-only \`/text-center/api/status\`, \`/discovery\`, \`/pages\`, \`/capabilities\` routes. API and asset routes both require trusted, authenticated TLS Kit portal context, exact host allowlist and authorized owner; a client-provided header cannot satisfy trust.
- \`prototype/text_center_kit_preview.js\` and \`prototype/text_center_kit_mode.css\` preserve the original source HTML structure and CSS appearance, adding responsive **Modern / Classic Teletext** viewing, keyboard \`g\` shortcut, numbered page 100–899 navigation, ten original major categories and passive device/capability status. Browser-local mode preference is currently persistent only on that device; **per-user synchronized mode preference and actual source pages/bookmarks/subpages are not implemented**. Untrusted content is inserted only as \`textContent\`.
- This is deliberately a **read-only INTEGRATION PREVIEW**. It does not claim the original web app's complete API functions/flows are available, cannot fetch official news, does not run FM/DAB/DVB scan/RDS, does not post on BBS and cannot persist bookmarks or real page history. These still require correct authentication, CSRF, shared source/cache storage, physical receiver leases and backend-specific contracts.
- The original source web directory and actual production owner-auth portal must first be installed; this PR only supplies WSGI mountable components. No standalone 8787 LAN listener, open HTTP host or fake browser HTTPS test was created.
- Fixture tests verify original markup rewrites and safe asset routes, disabled standalone app.js, no path traversal, source layout changes fail closed, owner/host/TLS trust requirements, no POST access and consistent GET API data. JavaScript syntax is now checked in the existing Stage4/5 GitHub Actions workflow.
